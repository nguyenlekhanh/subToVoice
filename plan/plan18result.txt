12. FOLLOW-UP FIXES (authorised by the user after this log was first written)
================================================================================
The user was shown the findings below and explicitly chose to have the two
pre-existing bugs fixed as well as the encoding bug. That is the only reason this
section exists; everything above it is the original PLAN 18 scope.

12.1 FIX: the Piper child now gets an explicit UTF-8 stdio environment
     services/piper_service.py gains:
         def build_piper_child_env() -> dict:
             env = dict(os.environ)
             env["PYTHONIOENCODING"] = "utf-8"
             return env
     and the one synthesis subprocess.run() call now passes
     `env=build_piper_child_env()`.
     Why this is a correctness fix and not a preference: this module's contract is
     that it writes UTF-8 bytes to the child's stdin (`(normalized + "\n").encode
     ("utf-8")`), and Piper decodes stdin with the locale encoding. The two must
     agree, so the child's encoding is pinned rather than inherited. The parent's
     own PYTHONIOENCODING is left untouched; nothing is leaked to os.environ.
     `piper_version_for_command()` was deliberately NOT changed - the `--version`
     probe only exchanges ASCII and already decodes with errors="replace".

12.2 FIX: this module's diagnostic prints can no longer crash synthesis
     services/piper_service.py gains `_force_utf8_stdio()`, which reconfigures
     sys.stdout/sys.stderr to UTF-8 with errors="backslashreplace", skipping any
     stream that has no reconfigure() (StringIO under a test runner, or None under
     pythonw). It runs once at import and again at the top of synthesize(), because
     a caller may swap sys.stdout after import (which is exactly what
     redirect_stdout does in the tests).
     errors="backslashreplace" is a second line of defence: even if a sink somehow
     cannot take UTF-8, unencodable characters degrade to \uXXXX escapes instead of
     raising UnicodeEncodeError and aborting the synthesis.

12.3 FIX: the pre-existing test error
     tests/test_piper_service.py lines 362-363 unpacked 3 values from
     run_fake_synthesis(), which returns 4. Changed to unpack 4, matching the
     helper and the other 14 call sites. This was the minimal repair: the test's
     intent (result and recorded argv) is unchanged and no assertion was altered.

12.4 NEW TESTS (Piper-only, additive): class
     PiperChildStdioEncodingRegressionTest with 6 tests:
       - build_piper_child_env() pins PYTHONIOENCODING to utf-8
       - it inherits the rest of the environment (PATH matches; exactly one key added)
       - it does not mutate os.environ
       - a child launched with that env round-trips Vietnamese stdin byte-exactly
       - a child pinned to cp1252 demonstrably corrupts the same bytes
         (this is the regression the fix exists for, pinned explicitly so the test
         is deterministic on any machine)
       - synthesize() completes and still emits the Vietnamese text when sys.stdout
         is a strict cp1252 TextIOWrapper
     Suite: 65 -> 71 tests, 71 pass, 0 failures, 0 errors, 0 skipped.
