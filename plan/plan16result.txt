10. FIX: voice Combobox edit never committed (batch logged defaults)
- User report: Generate All Voices logged the default voice for every row.
- Root cause: the voice Combobox reused the Entry editor's FocusOut path,
  which schedules a save 100ms after focus loss. Opening the dropdown moves
  focus to the dropdown listbox, so the pending save fired while the user
  was still choosing and committed the ORIGINAL (default) value, destroying
  the editor mid-selection. Programmatic <Down> auto-open made the race worse.
- Exact files changed (app/ui.py only):
  - _start_voice_edit: no auto-open; FocusOut now routes to
    _on_voice_edit_focus_out (deferred 200ms cancel that only acts when a
    voice edit is still pending) instead of the Entry delayed-save. Explicit
    pick (<<ComboboxSelected>>) or Enter still commits; Escape abandons.
    The Treeview cell is only written on commit, so abandoning loses nothing.
    Added [VOICE ASSIGN] editing/current log on open.
  - _on_generate_all_voices: logs every captured (index, voice) pair before
    validation, proving what the batch actually saw.
- service/UI capture/synthesis code needed no change (verified correct).
